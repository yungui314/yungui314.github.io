自建不蒜子API——解决访客统计加载失败

发表于2026-01-15|更新于2026-05-23|建站
|总字数:1k|阅读时长:3分钟|浏览量:

一、问题背景

前几天发现博客侧边栏的「本站访客数」和「总浏览量」一直转圈，始终加载不出来。

排查发现，Butterfly 主题默认使用不蒜子 (Busuanzi) 作为访客统计服务。不蒜子的 API 托管在 busuanzi.ibruce.info，但该服务器早已无人维护，长期处于宕机状态。主题里虽然通过 sukkaw/busuanzi 的镜像 JS 绕过了一部分问题，但那仅仅是个 JS 文件的镜像，底层 API 调用的仍然是同一个已挂掉的服务器。

浏览器 F12 打开 Network 面板，busuanzi.ibruce.info 的请求始终 pending，最终超时——这就是原因。

二、解决思路

既然公有服务靠不住，那就自己搭一个兼容的 API。

核心需求很简单：

  1. 一个后端 API，接受页面请求，记录并返回 PV / UV 数据
  2. 一个前端 JS，替代原版 busuanzi.pure.mini.js，调用自己的 API 并更新 DOM
  3. 数据需要一个持久化存储

技术选型：

组件 选型 理由
后端 Vercel Serverless Function 免费，和 Waline 共用账号，无需额外注册
数据库 Upstash Redis 免费层够用（每天 1 万次命令），天然支持 HyperLogLog 做 UV 统计
前端 自写 bsz.js 保持与原版相同的 DOM 元素 ID，兼容 Butterfly 模板

为什么不用 Umami？ Umami 功能更全但也更重——需要 PostgreSQL 数据库 + 独立部署 + 后台管理。对于只需要「站点 PV / UV / 页面 PV」三个数字的场景来说，杀鸡用牛刀了。一个 Redis + 一个几十行的 Serverless Function 足矣。

三、搭建过程

3.1 创建 Upstash Redis

  1. 访问 upstash.com，GitHub 登录，进入 Console
  2. 点击 Create Database，Name 填 busuanzi，Region 选 Tokyo 或 Singapore
  3. 创建完成后，保存 UPSTASH_REDIS_URL 和 UPSTASH_REDIS_TOKEN

3.2 编写 API 与前端脚本

后端 API（api/busuanzi.js）核心逻辑：

  • 站点 PV：每次请求 INCR 自增
  • 站点 UV：用请求 IP + User-Agent 的 MD5 做 PFADD，HyperLogLog 自动去重
  • 页面 PV：按页面路径 hash 分别计数

3.3 部署到 Vercel

  1. 将项目推送到 GitHub 仓库
  2. Vercel 导入该仓库，设置环境变量 UPSTASH_REDIS_URL 和 UPSTASH_REDIS_TOKEN
  3. 部署完成后获得域名 busuanzi-api.vercel.app

验证两个端点：

  • https://busuanzi-api.vercel.app/api/busuanzi → 返回 JSON 数据
  • https://busuanzi-api.vercel.app/bsz.js → 返回 JS 脚本

四、总结

整个过程不到10分钟，核心代码不到 60 行。回顾一下：

  • 故障原因：不蒜子公有 API 长期宕机
  • 解决方案：Vercel Serverless Function + Upstash Redis 自建兼容 API
  • 关键点：保持与原版相同的 DOM 元素 ID，无需修改主题模板
