利用cloudflare加速GitHub Pages博客访问

发表于2025-07-30|更新于2026-05-22|杂项
|总字数:1.5k|阅读时长:4分钟|浏览量:

一、前言 (为什么需要 CDN?)

对于许多国内开发者和博主而言，使用 GitHub Pages 托管个人博客是一个方便且免费的选择。但随之而来的问题是，由于网络环境的复杂性，国内用户直接访问 *.github.io 域名的速度往往不尽人意，甚至可能出现无法访问的情况。

为了解决这一痛点，我们可以引入 CDN (Content Delivery Network)。CDN 的原理是将你的网站内容缓存到全球各地的边缘节点服务器上。当用户访问时，CDN 会智能地将请求引导至离用户最近的节点，从而大幅缩短加载时间，提升访问体验。

虽然国内有许多优秀的 CDN 服务商，但它们大多是收费的。因此，本文将目光投向了 Cloudflare。作为全球领先的网络服务提供商，Cloudflare 提供了功能强大的免费 CDN 服务。尽管其免费套餐的节点主要分布在海外，但对于优化 GitHub Pages 的访问速度而言，效果依然立竿见影。其免费版 10万次/天 的请求限制，对于个人博客来说绰绰有余。

下面，我们学习一下如何为 GitHub Pages 博客配置 Cloudflare 加速。

二、准备工作

在开始之前，请确保你已具备以下两个条件：

  1. 一个已经搭建好的 GitHub Pages 博客。
  2. 一个你拥有的、可以修改 DNS 设置的域名。

本文假设你已经拥有了自己的域名。如果你还没有，可以在腾讯云、阿里云、NameSilo 等域名注册商处购买。例如，笔者在阿里云购买的 88mo.cn 域名，一年也仅需二十多元，性价比很高。下面就以此域名为例，开始配置。

三、配置教程

第 1 步：在 Cloudflare 添加你的站点

  1. 访问 Cloudflare 官网，注册并登录你的账号。

  2. 在控制台主页，点击 “+ 添加站点” 或 “Onboard a domain”。

  3. 输入你的根域名（注意：不要带 www 或 https 等前缀），例如直接填写 88mo.cn，然后点击“继续”。

  4. 选择套餐计划。对于个人博客，Free (免费) 套餐完全足够。

第 2 步：配置 DNS 记录指向 GitHub Pages

Cloudflare 会自动扫描你域名现有的 DNS 记录。如果是新域名，扫描结果可能为空，这很正常。现在，我们需要手动添加记录，将域名指向 GitHub Pages 的服务器。

  1. 删除所有可能存在的、与你的域名相关的 A、AAAA 或 CNAME 记录，以避免冲突。

  2. 点击“添加记录”，按照下图所示，创建 4 条 A 记录。

    • 类型 (Type): A
    • 名称 (Name): @(这代表你的根域名)或者直接写域名
    • IPv4 地址 (IPv4 address): 分别填写以下四个 IP 地址
    • 代理状态 (Proxy status): 保持橙色云朵图标，表示“已代理” (Proxied)

    你需要依次创建四条记录，唯一的区别是 IP 地址不同：

    • 185.199.108.153
    • 185.199.109.153
    • 185.199.110.153
    • 185.199.111.153

  3. 添加完成后，你的 DNS 记录列表中应该包含如下四条记录：

    [图片：Cloudflare DNS 记录列表，清晰地展示了已添加的四条指向 GitHub Pages IP 的 A 记录]

  1. 确认记录无误后，点击“继续”。

第 3 步：修改域名的名称服务器 (Nameservers)

接下来，Cloudflare 会要求你将域名的名称服务器 (Nameservers) 修改为 Cloudflare 指定的地址。这是最关键的一步，它意味着你将域名的解析权正式委托给了 Cloudflare。

  1. Cloudflare 会提供两个名称服务器地址。请复制并保存这两个地址。

  2. 登录你的域名注册商控制台（例如腾讯云、阿里云、NameSilo等）。

  3. 找到你域名的 DNS 或名称服务器管理页面，将默认的名称服务器地址更改为上一步从 Cloudflare 获得的那两个地址。

  4. 保存更改。名称服务器的变更在全球生效需要一些时间，短则几分钟，长则可能需要数小时，请耐心等待。

  5. 修改生效后，返回 Cloudflare 页面。你可能会看到一个快速入门指南，可以根据引导开启 始终使用 HTTPS 等推荐设置。当看到 “您的网站或应用程序现在已在 Cloudflare 保护之下” 的提示时，说明配置已成功。

第 5 步：配置 HTTPS 加密模式

为了保证网站安全并避免潜在问题，正确配置 Cloudflare 的 SSL/TLS 加密模式至关重要。

  1. 在你的 Cloudflare 站点管理页面，转到左侧的 “SSL/TLS” -> “概述 (Overview)”。

  2. 在这里，你会看到几种加密模式，这里选这里选择灵活、完全、完全（严格）都是可以的。

不推荐选择 “灵活”

  • 灵活 (Flexible): 浏览器到 Cloudflare 是加密的 (HTTPS)，但 Cloudflare 到 GitHub 服务器是未加密的 (HTTP)。如果你在 GitHub Pages 中开启了 “Enforce HTTPS”，这将导致 无限重定向 的问题，使网站无法访问。该问题可以通过规则来强制使用HTTPS解决，效果其实和选完全是一样的。
  • 完全 (Full): 端到端都是加密的，但 Cloudflare 不会验证源服务器（GitHub）的 SSL 证书是否有效。
  • 完全 (严格) / Full (Strict): 端到端都是加密的，并且 Cloudflare 会严格验证源服务器的 SSL 证书。这是最安全的选择，因为 GitHub Pages 会为你的自定义域名提供有效的证书。

四、大功告成

到此为止，所有的配置都已完成。现在，通过你的自定义域名访问博客，会发现网站加载速度有了显著提升。

此外，还可以在 Cloudflare 的“概述 (Analytics)”面板上查看详细的访问数据统计。
